decklog 只给带 Referer 的请求回卡组，浏览器 JS 设不了这个头、也读不到跨域响应。所以「读取」按顺序尝试：① 本站 /api/decklog（Vercel 等支持服务端函数的托管才有，同源、最省事）；② 你填的「代理地址」；③ 直连（基本会被拦）。

如果本站是 GitHub Pages 这类纯静态托管，①②都没有，请用下面两种方式之一：① 部署 decklog-proxy-worker.js（Cloudflare Worker，5 分钟）把地址填到上面的「代理地址」；② 用 取decklog卡组.bat 取到 JSON，粘到下面的框里。

解析规则与 decklog 导入插件一致：只认 game_title_id = 6（Shadowverse EVOLVE），主牌组取 list、进化牌组取 sub_list、主战者取 p_list。

规则与数据说明

与一键升罕插件使用相同的编号评分规则。同档最高罕保留原版本；从其他罕贵度升级到 PR 时，选择编号最大的 PR，编号按数字大小比较；升级到其他最高档时，取版本表中第一个最高档版本。PR 只按卡包名识别，BP21-PR02 归入闪卡档，UT 不归入 UR。

主战者编号始终原样保留，不参与升罕。未知卡牌编号原样保留并提示。本工具仅替换印刷版本，不检查卡组是否合法，不修改游戏或卡组文件。输出码内容相同但压缩方式可能与游戏不同，因此字符串长度可能不同。

decklog 导入：卡组码就是 https://decklog.bushiroad.com/view/<码> 的最后一段。decklog 的接口只给自己的站内 POST 回数据，浏览器的跨域请求读不到响应，所以页面上的「读取」通常会失败——用同目录的 取decklog卡组.bat 取到 JSON 再粘进来即可。解析规则与 decklog 导入插件一致：只认 game_title_id = 6（Shadowverse EVOLVE），主牌组取 list、进化牌组取 sub_list、主战者取 p_list[0].card_number；主战者同样原样保留。
